# Production-readiness audit — 2026-10-28 (first pass)

Scope of this pass: automated checks plus a targeted read of the riskiest surfaces. **It is not a line-by-line review of every module, and nothing here was run on a real PC.** Severity: High = could lose data or blank the app; Medium = wrong or insecure in a plausible case; Low = polish.

## Fixed in this pass
| # | Severity | Finding | Fix |
|---|---|---|---|
| 1 | High | **No error boundary.** One render error in any screen would blank the whole window (main, note and pet windows). | `ErrorBoundary`: calm message with Try again / Reload (data is in the database, untouched); the pet window retries quietly up to three times. 3 tests. |
| 2 | Medium | `pnpm audit --prod`: 5 advisories (1 high, 3 moderate, 1 low) in `vite` 7.3.6 (dev-server file-serving and `launch-editor`). Not in the shipped app (the bundle is static), but it is the developer machine. | `vite` 7.3.7. Audit now clean; build and tests pass. |
| 3 | Medium | Our own five characters failed the new alignment check (clipped frames, bobbing feet). | Rebuilt through the aligned pipeline (see CHANGELOG). |
| 4 | Medium | Four hand-rolled "click twice to confirm" flows (task row, label, meeting, task editor) that were easy to click through, and links that deleted without asking in one place. | One shared `ConfirmAction` everywhere. |

## Pass 3 (same day): Rust advisories, release-build speed, time-tracking review

| Area | Result |
|---|---|
| **Rust dependency advisories** (`cargo audit`, 2026-10-28) | **3 vulnerabilities, all in `zip` 2.6.1** (RUSTSEC-2026-0367/0368/0369: symlinks and SUID bits when *extracting* an archive). Loaf never calls `extract` and never sets file permissions (it unpacks only named files itself), so it was not exploitable, but the fix was one line: `zip` 9.1.3. It compiled unchanged; 455 core tests, clippy and `cargo audit` pass. 6 warnings remain, none a vulnerability: `proc-macro-error`, `zbus_names`, `zvariant`, `zvariant_derive` (unmaintained, pulled in by Tauri's Linux stack), `glib` 0.18 and `tokio` 1.53.2 (unsound API corners we do not use). They need upstream Tauri/tokio releases; re-check on each release. |
| **Export / import speed** | The 14.7 s / 26.4 s in pass 2 were a *debug* build. In a **release** build at the same size (50,000 notes, 50,000 tasks, 250,000 app sessions, 50,000 site sessions): migrate 2.0 s, **export 3.1 s, import 5.4 s**. Import now reuses one prepared statement. A progress message is no longer needed at this size. |
| **Time tracking, deeper read** (`usage.rs`, `usage_collector.rs`) | Clock going backwards (events are never moved back), sleep or a clock jump forward (the session ends at the last look), idle, lock screen, 12 h cap, midnight, DST and half-hour zones, and a time-zone change (stored as UTC, grouped by the zone at read time) all behave correctly in the code and tests. **One real gap, not fixed:** the stretch in progress is kept only in memory and written when it ends, and finished stretches wait up to 60 s before being saved. If Loaf is killed, the PC loses power or Windows crashes, that open stretch is lost (up to 12 h, normally minutes). A clean quit and a normal sleep save it. See "Open" for the options. |

**Answer to "did 0.5.2 fix the time-tracking edge cases?" No.** 0.5.2 changed no time-tracking code. Pass 2 only confirmed that the existing tests cover the edge cases and added one more test (hour buckets across DST and half-hour zones). This pass read the logic again and found the crash-loss gap above.

## Checked and fine
- **Network:** no listener, no HTTP client in `loaf-core` or `src-tauri`. Local-first holds.
- **Webview:** CSP `default-src 'self'; connect-src ipc:…; img-src 'self' data:`; three capability files, each with only the permissions it uses (events, drag, close, open-url).
- **Links:** only `http`, `https`, `mailto` open (`links.rs`, tested against `javascript:`, `file:`, `data:`).
- **ZIP / pet import:** paths that escape the folder, links and oversized files are refused; only named files are unpacked; `loaf.json` is re-written from checked values.
- **Panics:** 5 `expect`/`unwrap` outside tests (clock fake, a reader-pool permit, app start); none on user input.
- **Icon-only buttons:** all have an accessible name.
- Core is free of Tauri crates (`pnpm check:core-deps`).

## Open (not fixed; owner decides or later pass)
- `cargo audit` is not part of CI yet; add it (the six remaining warnings need an allow-list). Re-run on every release.
- **Time tracking loses the open stretch if Loaf is killed or the PC loses power.** Option A (recommended): every 10 minutes close the stretch and reopen it at the same instant, so at most 10 minutes can be lost; the cost is that the "sessions" count shown per app goes up for long stretches. Option B: save a marker row for the open stretch every minute and recover it at start; no count change, needs a migration. Your decision.
- No coverage tool is wired; test counts are 401 TS, 429 Rust, 15 Python.
- `src/ipc/settings.ts` still has a hand-written type with a TODO to generate it from Rust.
- Ghosty's sheet has a floor shadow ellipse; the Codex pet rules forbid shadows in generated art. Cosmetic for our own character.
- Every OS-dependent behaviour remains **Unverified** (see PROJECT_STATUS): pet movement, fullscreen hiding, right-click menu, Store app names, nudges.
- Not yet reviewed in depth: restoring a backup from the blocking screen (S-90) on a real PC, a real screen reader (NVDA/Narrator), performance of the UI lists with thousands of rows in the real window.
