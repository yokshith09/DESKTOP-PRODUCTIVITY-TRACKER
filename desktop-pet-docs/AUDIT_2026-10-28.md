Scope of this pass: automated checks plus a targeted read of the riskiest surfaces. **It is not a line-by-line review of every module, and nothing here was run on a real PC.** Severity: High = could lose data or blank the app; Medium = wrong or insecure in a plausible case; Low = polish.

## Pass 3 (same day): Rust advisories, release-build speed, time-tracking review

| Area | Result |
|---|---|
| **Rust dependency advisories** (`cargo audit`, 2026-10-28) | **3 vulnerabilities, all in `zip` 2.6.1** (RUSTSEC-2026-0367/0368/0369: symlinks and SUID bits when *extracting* an archive). Loaf never calls `extract` and never sets file permissions (it unpacks only named files itself), so it was not exploitable, but the fix was one line: `zip` 9.1.3. It compiled unchanged; 455 core tests, clippy and `cargo audit` pass. 6 warnings remain, none a vulnerability: `proc-macro-error`, `zbus_names`, `zvariant`, `zvariant_derive` (unmaintained, pulled in by Tauri's Linux stack), `glib` 0.18 and `tokio` 1.53.2 (unsound API corners we do not use). Import now reuses one prepared statement. A progress message is no longer needed at this size. |
| **Time tracking, deeper read** (`usage.rs`, `usage_collector.rs`) | Clock going backwards (events are never moved back), sleep or a clock jump forward (the session ends at the last look), idle, lock screen, 12 h cap, midnight, DST and half-hour zones, and a time-zone change (stored as UTC, grouped by the zone at read time) all behave correctly in the code and tests. **One real gap, not fixed:** the stretch in progress is kept only in memory and written when it ends, and finished stretches wait up to 60 s before being saved. Pass 3 found the crash-loss gap above; **pass 4 (2026-10-29) fixed it** with the crash journal (migration 011, see below).

## Pass 5 (2026-10-30): time-tracking accuracy, line by line

Scope: foreground event (`src-tauri/src/tracking.rs`) → `Tracker` and idle rules (`usage.rs`) → collector (`usage_collector.rs`) → journal → `store` → `summary` → dashboard (`useUsage`, refetch every 30 s).

| # | Finding | Evidence | Status |
|---|---|---|---|
| 1 | **Total climbs, then falls back.** `live_now` replaced the tracker's end with *now*, ignoring "input stopped here"; the idle limit then closed the stretch at the last input. | Collector test series before the fix: 0, 60, 120, 180, 240, 300, then 60 s. This is the reported 50 → 47. | Fixed |
| 2 | **A closed session is in no total until saved.** It waited up to 60 s in the collector's list; `summary` read only the database and the live stretch. | Test: 10 min in one app, switch, total showed 5 instead of 15 min. | Fixed (waiting list is part of the totals; one gate for read and write) |
| 3 | **No input is read as "away", even for a film or a call.** 5 minutes without keyboard or mouse ends the stretch; the rest of the call or film is lost. Differs by PC with the use (headset calls, controllers, tablets, video) which is why some PCs "record less". | Code path `poll` → `Idle{last_input}`. Test: 40 min call counts only with a held screen. | Fixed for films, calls and presentations (up to 2 h); controllers and tablets that do not hold the screen on are still read as away |
| 4 | **A missed focus event is never corrected.** With nothing in front there was no timer, so the tracker stayed on "nothing" until the next switch. | Design read; test with a fake platform whose events are lost. | Fixed (the look asks the OS which window is in front) |
| 5 | **A clock set back freezes the stretch.** Event times are clamped to the latest seen, so the stretch stayed at the old time until the clock caught up, and the live stretch disappeared from the totals. | Three tests. | Fixed (30 s threshold) |
| 6 | **Sleep and hibernation** | A gap over 150 s between looks ends the stretch at the last look: up to one look (about a minute) before sleep is lost. | Stated limit (needs a power event to do better) |
| 7 | **Fullscreen.** The foreground hook has no special case for full screen: a full-screen window is still the window in front, and tracking continues. The only fullscreen losses are no input for 5 min (3, fixed for films and calls) and programs that deny the process query. | Code read: `on_foreground` → `report`. Not run on a real PC. | Answered |
| 8 | **Alt+Tab, lock screen, UAC.** The task switcher and sub-2-second blips are not counted (about 1–3 s per switch); the lock screen is ignored on purpose. | | Stated limit |
| 9 | **Protected / anti-cheat programs** deny the process query and record nothing. Counting them would also count the lock and sign-in screens. | | Stated limit; owner may choose a "not readable" row later |
| 10 | **Differences between PCs.** Input hardware (idle clock), power requests held by other software (can only add time, capped at 2 h), clocks that step, protected programs, macOS versus Windows foreground sources. | | Explained, not all removable |

Not verified: all Windows behaviour (the code compiles for `x86_64-pc-windows-gnu`; nothing ran), and the macOS power-assertion code (compiled only in CI). Whether `CallNtPowerInformation(SystemExecutionState)` reports the power requests browsers and Zoom make is the assumption to check on the owner's PC first: play a video with the hands off the machine for 8 minutes and see whether it keeps counting.

## Checked and fine
- **Network:** no listener, no HTTP client in `loaf-core` or `src-tauri`. Local-first holds.
- **Webview:** CSP `default-src 'self'; connect-src ipc:…; img-src 'self' data:`; three capability files, each with only the permissions it uses (events, drag, close, open-url).
- **Links:** only `http`, `https`, `mailto` open (`links.rs`, tested against `javascript:`, `file:`, `data:`).
- **ZIP / pet import:** paths that escape the folder, links and oversized files are refused; only named files are unpacked; `loaf.json` is re-written from checked values.
- **Panics:** 5 `expect`/`unwrap` outside tests (clock fake, a reader-pool permit, app start); none on user input.
- **Icon-only buttons:** all have an accessible name.
- Core is free of Tauri crates (`pnpm check:core-deps`).
